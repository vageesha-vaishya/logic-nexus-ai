## Context

`public.amro_*` has 56 tables. 32 are unambiguously AMRO and were
mirrored to `amro.*` in Phase 6 Step 58 (commit `d8796f5e`). The
remaining 24 tables are inventory- or part-related and overlap with
UIM's mandate as the platform's "Universal Inventory Master":

```
amro_inventory_*               (4 tables: health_overview, reorder_queue,
                                scan_events, work_order_links)
amro_item_master               (1 — the canonical item table)
amro_item_cross_references     (1)
amro_item_uom_conversions      (1)
amro_part_interchangeability   (1)
amro_parts_demand_overview     (1)
amro_parts_mro_workflow_events (1)
amro_stock_*                   (12 tables: ledger, balances, valuation,
                                approval queue, period closes, reconciliation,
                                audit timeline/export)
amro_uim_*                     (2 tables: inventory_sync_events, seed_validation)
```

The 2026-06-01 audit flagged this as a design block — shipping these
tables prematurely as `amro.*` mirrors would require a delete-and-
recreate dance once UIM canonical inventory lands. The audit pinned
22+ open AMRO + UIM items on this decision.

## Decision

**UIM owns canonical inventory. AMRO carries thin aviation-regulatory
extensions keyed by `uim.item_master.id`.**

Both module authors arrived at this independently (amro.md §9.1 and
uim.md §9.4) and the wording is aligned:

> amro.md §9.1: "UIM owns `inventory_items` / `inventory_ledger` /
> `inventory_locations` as the **primary store**; AMRO has
> `part_profiles` + `inventory_extensions` for aviation-specific
> metadata (life-limited, ATA chapter, calibration intervals).
> Consumption of parts publishes `amro.work_order.parts_consumed` →
> UIM ledger movement."

> uim.md §9.4: "AMRO uses `uim.inventory_*` as primary store; AMRO's
> own `amro_inventory_*` becomes a thin AMRO-specific extension
> layer (life-limited parts, calibration intervals, aviation
> regulatory metadata) keyed by `item_id`. The 12+ AMRO inventory
> tables consolidate to ~3 extension tables."

This ADR ratifies that direction.

## Classification of the 24 deferred tables

### → `uim.*` (canonical inventory; 19 tables)

The store-of-truth state. Lives in UIM under `inventory.*` (or `uim.*`
flat — both authors hedge on whether to namespace; this ADR picks the
flat naming to mirror existing schema conventions across the platform).

| public.* (source)                       | uim.* (target)                  | Notes |
|---|---|---|
| `amro_item_master`                      | `uim.item_master`               | Item canonical — the BIG one |
| `amro_item_uom_conversions`             | `uim.item_uom_conversions`      | Unit-of-measure conversions per item |
| `amro_item_cross_references`            | `uim.item_cross_references`     | OEM/alt/internal part-number cross-refs |
| `amro_part_interchangeability`          | `uim.part_interchangeability`   | "this part can substitute for that part" |
| `amro_inventory_scan_events`            | `uim.inventory_scan_events`     | Barcode/RFID scan stream |
| `amro_inventory_reorder_queue`          | `uim.inventory_reorder_queue`   | Below-min reorder triggers |
| `amro_inventory_health_overview`        | `uim.inventory_health_overview` | Likely view; recreate over uim tables |
| `amro_stock_ledger_transactions`        | `uim.stock_ledger_transactions` | Append-only ledger; partitioned per §3 |
| `amro_stock_ledger_current_balance`     | `uim.stock_ledger_current_balance` | Materialised balance projection |
| `amro_stock_balance_summary`            | `uim.stock_balance_summary`     | View over current_balance |
| `amro_stock_approval_queue`             | `uim.stock_approval_queue`      | Movements awaiting approval |
| `amro_stock_audit_export`               | `uim.stock_audit_export`        | View for audit-export download |
| `amro_stock_audit_timeline`             | `uim.stock_audit_timeline`      | Chronological audit projection |
| `amro_stock_period_closes`              | `uim.stock_period_closes`       | Inventory period closes |
| `amro_stock_reconciliation_items`       | `uim.stock_reconciliation_items` | Cycle-count diffs |
| `amro_stock_reconciliation_runs`        | `uim.stock_reconciliation_runs` | Cycle-count run metadata |
| `amro_stock_valuation_consumptions`     | `uim.stock_valuation_consumptions` | FIFO/AVCO consumption journal |
| `amro_stock_valuation_layers`           | `uim.stock_valuation_layers`    | Cost layers for valuation |
| `amro_stock_valuation_summary`          | `uim.stock_valuation_summary`   | View |

### → `amro.*` (aviation regulatory extensions; 3 tables)

Aviation-specific metadata that has no meaning outside AMRO. Each row
is keyed by `uim.item_master.id` (per the ADR's "thin extension"
principle); FKs to the canonical UIM tables.

| public.* (source)                  | amro.* (target)              | Notes |
|---|---|---|
| `amro_inventory_work_order_links`  | `amro.work_order_item_links` | Joins AMRO work orders to UIM items consumed; AMRO concern |
| `amro_parts_demand_overview`       | `amro.parts_demand_overview` | Maintenance-schedule-driven demand forecasting; aviation-specific |
| `amro_parts_mro_workflow_events`   | `amro.parts_mro_workflow_events` | MRO workflow (overhaul/repair tracking) — aviation-specific |

Two **new** tables to be created (NOT migrations of existing data):
- `amro.part_profiles (id, item_id FK→uim.item_master, life_limited boolean, ata_chapter, calibration_interval_hours, ...)`
- `amro.inventory_extensions` — aviation regulatory metadata per item (per amro.md §9.1)

### → Drop / sync-redesign (2 tables)

| public.* (source)                  | Action                       |
|---|---|
| `amro_uim_inventory_sync_events`   | DROP — sync becomes outbox events (`amro.work_order.parts_consumed` → UIM consumer per amro.md §9.1) |
| `amro_uim_seed_validation`         | DROP — ephemeral validation table; not needed in canonical schema |

## Implementation order

Phased to avoid breakage and follow the Phase 6 dual-write pattern:

1. **Phase 6 Step 61** (next): `CREATE SCHEMA uim` + LIKE-mirror the 19 canonical tables (via Step 57 codegen). Backfill + dual-write triggers. Same shape as Step 58. ~150 LOC.
2. **Step 62**: LIKE-mirror the 3 AMRO-extension tables to `amro.*` (also via codegen). Smaller batch.
3. **Step 63**: Create the new extension tables (`amro.part_profiles`, `amro.inventory_extensions`) per amro.md §9.1 with FKs to `uim.item_master`.
4. **Step 64**: Replace `amro_uim_inventory_sync_events` with an outbox emitter on `public.amro_work_orders` for the `amro.work_order.parts_consumed` event (via Step 55 emit-trigger codegen).
5. **Step 65**: Drop `amro_uim_seed_validation` (and the legacy `amro_uim_inventory_sync_events` after a parity window).
6. **Step 66** (calendar-gated, post-30-day): Drop the 24 `public.amro_*` legacy tables.

`services/amro-api/` and `services/uim-api/` consumers cut over to read from the canonical schemas as part of Steps 61-64, not after.

## Consequences

**Positive:**
- Single source of truth for inventory state. Cross-module reads (CRM, finance, logistics) all point at `uim.*`.
- AMRO retains aviation-specific concerns (life-limited, ATA chapter) without owning a duplicate item catalog.
- 19 tables consolidate to 1 namespace. Maintenance footprint shrinks.
- Outbox event replaces sync-table polling — fits the rest of Phase 6's pattern.

**Negative / costs:**
- Cross-schema FKs: AMRO extension tables FK to `uim.item_master`. PG supports this fine but breaks the "module owns its FKs" purity goal. Acceptable per master plan §2.6.
- Migration window: until Step 66, AMRO + UIM consumers both read mirrors via dual-write triggers (2x storage temporarily).
- Cutover risk on `amro_stock_ledger_transactions` — large table; backfill needs an off-hours window. Mitigated by the append-only + partition-by-date pattern.

**Out of scope (parked):**
- `inventory.*` vs `integration.*` sub-namespacing within UIM (uim.md §9.1 — recommend NO for v1).
- GraphQL subgraph design (uim.md §9.2).
- LLM features for inventory field-mapping / DLQ-triage (uim.md §7).
