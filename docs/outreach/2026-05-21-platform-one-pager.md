## What it is

A consumer mobile app (Android first, web companion) that helps Indian retail investors run a goal-anchored, three-tier portfolio. The platform **interprets** a proprietary signal engine's output in plain language, **never originates** buy/sell recommendations on its own, and **never custodies** user funds — execution always runs through the user's existing broker via OAuth.

Planned public launch: **Q1 2027**, ahead of the April 1 2027 SEBI deadline.

---

## What the user sees (four surfaces, all interpretation-only)

1. **Portfolio tab.** Three tiers (Foundation / Growth / Opportunistic) the user assigns on onboarding. Card showing realized long-term capital gains for the current FY against the ₹1.25 L exemption. No advice — pure status.
2. **Home tab — Risk Score card.** A 0–10 daily score computed from concentration, plan drift, drawdown, and beta. Compared against the user's onboarded target. Elevated state offers a "How to fix" CTA which opens an existing rebalance recommendation; user-confirmed only.
3. **Home tab — Holdings-aware Market Commentary.** Last-24h news headlines for the user's top-3 holdings, sourced from a market news pipeline. **Headlines are surfaced verbatim today.** An LLM-summarisation layer is built but **production deploy is gated on your sign-off** of the prompts and a 500-sample output dump.
4. **Signals tab.** A proprietary signal engine emits trade ideas with confidence chips. An LLM adds a 2–3-line plain-language **explanation** of each signal. The signal itself is generated by the engine, not the LLM. The user must explicitly tap and biometrically confirm to execute.

A **Portfolio Health Diagnostic** card (daily LLM-generated interpretation of the user's tier mix, drift, and risk score) is also built and **on the same compliance gate** as surface 3.

## Where the LLM sits

The LLM is **downstream** of trade-idea generation. Architecturally:

```
[Market data] → [Proprietary signal engine] → [Signal record, with confidence + thesis fields]
                                                                  ↓
                                                  [LLM: explain this signal in plain language]
                                                                  ↓
                                                  [User reads explanation, decides]
                                                                  ↓
                                                  [User taps "Execute" + biometric confirms]
                                                                  ↓
                                                  [Order sent to user's connected broker]
```

The LLM is never given the prompt "should the user buy this?" — it is given a structured signal and asked to **describe it**. Prompts explicitly include the instruction "do not recommend buy or sell." Outputs are intended to fall on the **research-analyst-style commentary** side of the line, not the investment-adviser personalized-recommendation side. Whether that intent matches the regulator's reading is the central question we are engaging you to answer.

## Architecture facts that may matter to you

- **No custody.** The platform holds no user funds at any time. Execution is via the user's own Zerodha (Kite Connect) or Fyers OAuth at launch; Dhan / Angel One / ICICI / Kotak in later waves.
- **No discretionary management.** Every trade requires per-trade biometric confirmation on-device. The recommendation payload (signal id, prompt, LLM output, score components, timestamp) is logged at the moment of confirmation as a tamper-evident audit row.
- **KYC.** Broker-passthrough — no aggregator KYC. Identity is what the broker has on file; the platform reads name + masked PAN + demat from the broker after OAuth.
- **Rebalancing.** Drift-based detector recommends a basket of trades when any tier's actual allocation drifts > ±5 % from the user's onboarded target. The basket is shown end-to-end with brokerage cost; user confirms or dismisses. No auto-execute.
- **Data residency.** Supabase (Postgres + storage) in India region. LLM API calls go to OpenAI / Anthropic / Gemini via the worker's LLM gateway, configurable per-tenant.
- **Stack.** React 18 + Vite + TypeScript front-end, FastAPI Python worker, Capacitor Android shell. Same codebase between web and mobile.

## What we have built defensively against the RA / IA boundary

| Risk | Mitigation in code today |
|---|---|
| LLM hallucinating a recommendation | Prompts begin with "do not recommend buy/sell"; outputs reviewed in a per-route safety check before render. |
| User reading interpretation as advice | Every LLM-generated card carries a "What is this?" glossary entry explaining it's commentary, not advice. |
| Discretionary execution claim | Biometric per-trade confirmation; the audit row stores the prompt + output the user saw at confirmation time. |
| Stale data presented as fresh | News carousel pins a 24 h TTL; risk score is computed daily with the components stored alongside. |
| Concentration / over-trading nudge interpreted as advice | Three "mistake-prevention rails" warnings in the execution sheet (post-trade concentration > 25 %, STCG-window sell, SIP cancellation) — warnings only, never blocking. |
