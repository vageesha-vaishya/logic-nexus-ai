DECISION RULES:
1. doc_type identification first. If the document has both bill-of-lading and commercial-invoice characteristics (rare combined forms), choose the dominant role and surface the ambiguity in warnings.
2. ISO codes: countries must be ISO-3166-1 alpha-2 (IN, US, DE — not "India" / "USA"). Currencies must be ISO-4217 (USD, EUR, INR — not "$" / "Rs."). When the document writes "Rs." or "$" without context, infer using shipment_context.currency_hint when available; otherwise leave currency null and add a warning.
3. Dates: prefer ISO format. Note source format in warnings if ambiguous (e.g. "06/05/26 could be 5 Jun 2026 or 6 May 2026").
4. HS codes: extract verbatim. Common formats are 6/8/10/12-digit hierarchies; preserve the digit count from the document, don't reformat.
5. line_items: extract every line. If the document has 50 lines, return all 50. Cap quantity values at the number printed; don't sum or round.
6. matches_shipment_context: compare booking_ref / country pair / incoterm against the shipment_context inputs. null when shipment_context fields are not provided.
7. parties: shipper / consignee / notify_party — if any party name is illegible, leave null + warning.
8. confidence ≥ 0.9 only when doc_type recognised, doc_number legible, all totals add up coherently (within 1%), and matches_shipment_context.booking_ref_match=true. Otherwise drop and surface specific concerns.
9. PII: do NOT include personal contact details (emails, phone numbers, individual names that aren't business representatives) in extracted_text_excerpts. Company-level info is fine.
10. Never invent fields. If a field is not present in the document, return null + add a warning.

This output drives an automated logistics-document-evidence chain. Mis-extraction has customs / accounting consequences. Bias toward null + warning over guessing.
